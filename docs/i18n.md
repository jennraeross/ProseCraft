# Interface localization (maintainer notes)

Volunteer-facing instructions live in [CONTRIBUTING.md](../CONTRIBUTING.md#translating-the-interface).
This page is for maintainers: how the system works, how to add messages, and what is still English.

## Architecture

| File | Purpose |
| --- | --- |
| `src/lib/i18n/messages/en.json` | English source. Every other catalog is validated against it. |
| `src/lib/i18n/messages/<locale>.json` | One flat JSON file per language. Dropping a file in is enough to make it available. |
| `src/lib/i18n/catalog.ts` | Loads catalogs with `import.meta.glob`. English first, then native names. Hides `en-XA` from production. |
| `src/lib/i18n/message.ts` | AST parser and plain-text renderer. Handles placeholders, numbers, plurals, selects and inline tags. |
| `src/lib/i18n/format.ts` | Catalog lookup, English fallback and `renderMessage`. |
| `src/lib/i18n/state.svelte.ts` | Reactive `localeState`, `t()`, `setLocale()`, `<html lang/dir>`. |
| `src/lib/i18n/Trans.svelte` | Renders allowlisted inline tags as real elements. |
| `src/lib/i18n/validate.js` | Structural checks shared by the CLI and tests. |
| `scripts/i18n-check.mjs` | `npm run i18n:check` / `npm run i18n:status`. |
| `scripts/i18n-pseudo.mjs` | `npm run i18n:pseudo` QA catalog. |

## Adding a message

1. Add the English string to `en.json` with a semantic, namespaced key (`settings.data.exportBackup`,
   `search.noMatches`). Never use the English text as the key.
2. Use `t("key", { param })` in Svelte and TypeScript for plain text.
3. If the sentence contains inline emphasis or code, use `<Trans key="key" params={{ file: "vault.json" }} />`
   instead of `t()`. Allowed tags: `strong`, `em`, `code`, `kbd`; no attributes.
4. Translate the other catalogs, or leave them out — they fall back to English.
5. Run `npm run i18n:check`.

Rules that the checker enforces:

- placeholders (`{name}`) and plural/select parameter names must match English;
- every plural must have an `other` branch;
- plural selectors must be valid for the locale;
- tags must be lowercase, balanced, attribute-free and allowlisted;
- unknown keys and empty translations in a catalog are errors.

Missing translations are **not** errors. CI runs the non-strict check; maintainers can run
`npm run i18n:check -- --strict` when a language is declared complete.

## Commands

```sh
npm run i18n:check             # validate + coverage summary
npm run i18n:status            # Markdown table for a README or issue
npm run i18n:check -- --strict # also fail on incomplete locales
npm run i18n:pseudo            # generate en-XA pseudo-locale for QA
```

## Pseudo-locale QA

`npm run i18n:pseudo` writes a gitignored `en-XA.json` with accented text in brackets. It appears in
**Settings → General → Interface language** in development builds only. Use it to:

- spot hardcoded strings: they stay plain English while catalog text is bracketed and accented;
- find clipped labels and buttons, because bracketed text is longer;
- check plural branches, which are pseudo-localized inside the ICU syntax.

It is regenerated from `en.json` after message changes; do not commit it.

## Preview locales

Some catalogs are AI-drafted and intentionally partial. They are selectable in the app but marked
**Preview** in the language picker; untranslated keys fall back to English. Preview status is declared
in `PREVIEW_LOCALES` in `src/lib/i18n/catalog.ts`.

| Locale | Language | Status | Coverage |
| --- | --- | --- | --- |
| `de` | German | preview, complete, awaiting native review | 1566/1566 (100%) |
| `es` | Spanish (neutral) | preview, complete, awaiting native review | 1566/1566 (100%) |
| `fr` | French | preview, complete, awaiting native review | 1566/1566 (100%) |
| `pt-BR` | Brazilian Portuguese | preview, complete, awaiting native review | 1566/1566 (100%) |
| `it` | Italian | preview, complete, awaiting native review | 1566/1566 (100%) |
| `pl` | Polish | preview, complete, awaiting native review | 1566/1566 (100%) |

When a native speaker has reviewed a catalog and `npm run i18n:check -- --strict` passes for it, remove
it from `PREVIEW_LOCALES` and update this table. Use `npm run i18n:status` for live coverage.

The initial preview files cover the full catalog. They are AI drafts and have not had a native-speaker
review, so they are labelled **Preview** rather than supported. Useful first review targets:
neutral-Spanish “Ajustes” vs “Configuración”, Italian “Progressi” vs “Avanzamento”, French
typographic spacing, and Polish plural branches in the progress/comment counts.

## Translation platforms

The catalogs are plain flat JSON with ICU messages and a small HTML-like tag set, which Weblate,
Crowdin and inlang/Fink all support. Recommended settings:

- format: JSON, flat keys, do not reorder or rename keys;
- enable ICU plural/select handling;
- protect `strong`, `em`, `code`, `kbd` as inline tags and protect `{placeholders}`;
- configure the target path as `src/lib/i18n/messages/%two_letters_code%.json` (adjust for BCP 47
  tags such as `pt-BR`);
- let the platform open pull requests; CI runs `npm run i18n:check` on them.

Weblate is free for libre projects and is the recommended host; a self-hosted or Crowdin setup works
the same way because the repository contract is just the JSON files.

## What is still English

Approximate counts from a text-node scan, for planning. Do not treat them as exact: they include
some user content and exclude strings built in TypeScript.

| Area | Remaining |
| --- | ---: |
| Low-level sync schema/WebDAV error strings | ~25 |

At the time of writing the catalog holds 1564 keys. All `.svelte` text is localized, the user-facing
messages returned by modules for citations, Zotero, vault crypto/storage, sync providers, Google
Drive, EPUB import and cover generation are localized, and the **native Tauri menu** is localized
through the `set_menu_labels` command (called at startup and whenever the interface language
changes). Front/back matter preset titles (Epigraph, Foreword, …), citation style names and
`formatName` strings used in native save dialogs remain English as content/proper names; the starter
sample prose in `starterContent` is product content and is not translated through the catalog.

The remaining module prose is deep sync-folder schema validation (`storage/sync/layout.ts`,
`open-layout.ts`, WebDAV transport), which surfaces only for malformed or incompatible sync folders.

## Deliberately not translated (for now)

- **Stored values** — label colours, relation types, style ids, settings ids. Translate at render
  time, never change what is persisted.
- **Starter content** (`src/lib/starters.ts`) and export presets — product content, a separate
  translation effort with its own review process.
- **Brand and technical names** — ProseCraft, Citation Style Language, filenames, URLs, code.
- **User data** — project/chapter/scene titles, comments, wiki content.
- **Third-party/OS text** — native file dialogs and OS-localized menu items.

## Open decisions

1. **Export language.** UI language is separate from the manuscript language. PDF/DOCX/EPUB need a
   language setting for `lang`/`dc:language`, hyphenation and generated labels (“Contents”,
   “Untitled”). PDF fonts also need glyph coverage for CJK/Arabic. Not implemented.
2. **RTL.** The catalog and `<html dir>` support exist, but layout, icons and the storyboard canvas
   need an audit before Arabic/Hebrew/Persian/Urdu are offered.
3. **Proofreading.** Harper supports specific languages/dialects; hide or disable proofreading for
   locales it does not support.
4. **Native menu.** Labels are built in Rust; move them to the frontend or pass translated labels
   when rebuilding the menu.
5. **Dates and numbers.** Prefer `formatNumber`/`Intl` with the active locale; several
   `toLocaleString()`/`toLocaleDateString()` call sites still use the OS default.
